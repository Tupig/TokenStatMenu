# 统计口径

[返回文档中心](Home.md)

TokenStatMenu 同时展示几种不同来源。判断数字是否符合预期时，先确认来源、单位、记录时间和覆盖范围，再比较数值。

## 数据来源总表

| 项目 | 来源 | 单位 | 不能代表什么 |
| --- | --- | --- | --- |
| 5 小时、7 天企业额度 | Hub 只读后台响应中的明确窗口 | 金额、已用/剩余百分比、重置时间 | Token 数量、本机全部请求、模型瞬时吞吐 |
| 月度已用 | Hub 后台的月度金额字段 | 后台提供的币种或符号对应的金额 | 本机 Token 花费估算、自动汇率换算、完整财务账单 |
| 输入、输出与总 Token | 当前 provider 配置关联的本机 Codex 扫描记录 | Token | 企业全部消耗、从安装以来的总量、本次启动以来消耗 |
| 实时估算 | 活动轮次中连续累计 Token 事件的差分 | tok/s | 服务端逐 Token 瞬时速度或纯生成速度 |
| 上轮记录均速 | 有完整开始、累计与完成证据的轮次 | 输出 tok/s | 当前速度、排除工具等待的模型速度 |
| 顶层对话、子代理、分叉 | 扫描记录中的可识别身份与继承关系 | 线程/对话数量 | Codex 全部侧栏条目、网络请求数 |
| 本地额度快照 | Codex 记录内历史额度事件 | 原始比例、记录与重置时间 | 已确认的当前企业额度 |
| 可选界面兼容快照 | Token Hub 当前可访问界面 | 界面显示的金额与比例 | 已核验账号/组织的后台权威响应 |

## 企业 5 小时与 7 天窗口

当前显示的百分比最多保留两位小数，例如 `37.50%`。内部阈值比较不使用显示文本的四舍五入结果：79.995% 仍低于 80%，80.005% 已进入黄色区间；94.995% 仍低于 95%，95.005% 进入红色区间。缺失或歧义的 5 小时、7 天窗口分别保持未知，不能从另一窗口、月度或历史数据补齐。

直接读取按后台窗口种类识别 5 小时、7 天和月度数据，不用数组位置、金额大小或任意时间长度猜测归属。对应窗口提供合法的已用金额与额度后，计算：

```text
已用百分比 = 已用金额 / 窗口额度 × 100
剩余百分比 = 100 − 已用百分比
```

额度必须大于零，金额必须非负且不超过额度；重复窗口、不可核验的数字或结构异常会拒绝该响应，不把错误数据改成零。未知窗口种类不塞进 5 小时或 7 天槽位。

月度响应的 `quota_amount` 是可选总额。总额存在且有效时显示已用、总额、剩余、百分比和进度；只有已用金额时只显示已用，剩余、百分比和进度保持未知。月度金额不从滚动窗口或本地 Token 计数推断。

重置时间优先来自窗口的周期结束字段，必要时使用响应明确提供的重置字段，并按本机时区显示。没有足够字段时显示未知；界面兼容快照中的短时间文本不用于猜年份或时区。

月度已用只展示已确认的月度金额。它不表示已经实现“月度 Token 配额、剩余 Token、单价与累计花费”的完整账务功能。后台金额与本机 Token 不互换，也不通过自填价格补成企业账单。

## 快照时效

Hub 快照有效期为 `max(120 秒, 刷新间隔 × 2)`。默认刷新间隔 60 秒，因此默认有效期 120 秒。时间在未来、超过有效期或来源失效的快照不能作为当前菜单栏额度。Hub 退出、实例变化或旧请求迟到时，会丢弃或清除不再可信的结果。

后台直接读取与辅助功能兼容读取是独立来源。前者可用时优先展示；后者只在已有系统授权且额度区域可访问时尝试。界面快照的账户、组织和币种不能仅凭界面符号完成核验，界面文案会保留来源区别。

## 实时估算 token/s

本机 Codex 记录通常以累计事件提供用量，并不保证逐 Token 写入。应用在仍处于活动状态的同一轮次中，取得两条连续、时间顺序正确的累计事件后计算：

```text
输出估算 tok/s = (较新累计输出 − 较旧累计输出) / 两事件间隔秒数
输入估算 tok/s = (较新累计输入 − 较旧累计输入) / 两事件间隔秒数
```

例如合成记录在 2 秒内累计输出从 100 增至 149，则区间输出估算为 `24.5 tok/s`。这个结果描述两个事件之间的平均推进速度。输入值也只是输入累计推进的速率，不是网络上传速度、提示词编码速度或首 Token 延迟。

最后一次活动事件超过 15 秒，实时估算会失效。损坏事件、读取缺口、不完整尾行、重叠轮次、未来时间或倒序时间不能被跨过去拼接。刷新得更快不会创造新的 Token 事件，也不能用企业金额变化反推实时速度。

真实服务端瞬时吞吐目前尚无已接通的权威来源，继续由 [Issue #37](https://github.com/Tupig/TokenStatMenu/issues/37) 跟踪。

## 上轮记录均速

完整轮次需要可关联的开始、用量与完成证据，并有可验证的累计基线及轮次时长：

```text
上轮记录均速 = 该轮输出 Token 增量 / 整轮时长
```

整轮时间包含工具运行、网络和等待。长时间调用工具时，该值可能远低于模型生成期间的速度。无新鲜活动事件时，菜单栏可以回退展示上轮均速；“上轮均”不等于仍在生成。

## 本地用量与扫描范围

扫描读取 Codex 的 `sessions` 目录及同级 `archived_sessions` 归档目录。默认根目录为 `~/.codex`，可通过绝对路径的 `CODEX_HOME` 修改。两个目录各有独立缓存；同一文件的硬链接和同一线程的归档副本不重复计数。

| 上限 | 当前范围 |
| --- | --- |
| 枚举项 | 最多 5,000 项 |
| 物理文件 | 每目录最多 32 个 |
| 单文件开头 | 最多 64 KiB |
| 单文件结尾 | 最多 256 KiB |
| 单次总读取 | 每目录最多 10 MiB |

菜单栏只显示速度与 Hub 额度，Token 用量放在悬停详情和概览面板。用量仅覆盖本次可计算的记录，不是全部历史或账户账单；达到扫描上限时，详情会提示范围限制。

当前 provider 的 `base_url` origin 需要与 Hub 的既有连接 origin 关联，并且记录的 `model_provider` 需要匹配。**这只能证明当前配置关联，不能证明同名 provider 的历史会话过去一直走该网关。** 历史路由仍未核验，不能把这些记录当作企业后台总账。

## 线程身份、继承与会话计数

同一逻辑线程可能对应重复文件，子代理或分叉还可能继承父记录。应用只有在身份、连续边界和继承基线足够可靠时才核算贡献，避免把继承的 Token 再加一次。

| 标签 | 含义 |
| --- | --- |
| 线程 | 当前扫描内可按规则核算的逻辑线程 |
| 其他线程 | 已发现身份，但贡献或继承证据不足的线程 |
| 未识别物理文件 | 缺少可靠线程身份的文件 |
| 已识别顶层对话 | 当前扫描中可识别为顶层的对话，不含所有子代理/分叉 |
| 子代理 / 分叉 | 已识别的线程关系分类，不是额外网络请求 |

线程分类只说明记录是否可计算，不证明历史会话的企业账号、组织或网关路由。存在未知贡献时只汇总可计算部分，未知不按零处理。线程与顶层对话数量仅在详情中显示。

## 缓存读取、未缓存输入与命中率

在概览中展开“缓存与线程轮次明细”即可查看这些字段，不需要填写配置。Codex 的输入累计值已经包含缓存读取：

```text
I = 来源输入 Token（包含缓存读取）
C = 来源明确提供的 cached_input_tokens
U = 未缓存输入 = I − C
```

例如输入 100、缓存读取 35 时，未缓存输入是 65。缓存不是需要再次加入总量的额外消耗；reasoning 等输出子集也不重复加入总量，仍保留来源的合法总 Token 值。

| 缓存字段状态 | 显示与处理 |
| --- | --- |
| 合法整数，包括明确的 0 | 展示数值；同一输入范围内计算未缓存输入和比例 |
| 未提供或 null | 显示“来源未提供”，不补零、不回退旧值 |
| 负数、布尔、分数、超出整数范围或大于输入 | 显示“来源值无效”；其他合法输入、输出和总量仍保留 |
| 累计链回退或缓存增量大于输入增量 | 该链的缓存统计无效；完整线程和单个完整轮次分别核对 |

命中率使用同一有效覆盖内的 `sum(C) / sum(I)`，不平均每行百分比。例如两线程输入/缓存分别为 `100/90`、`900/90`，汇总命中率是 `180/1000 = 18.00%`，不是 50%。如果第二个线程未提供缓存，整个范围的缓存、未缓存输入和命中率保持未知；“同覆盖匹配合计”可以单独显示 `90/100 tokens`，并标明只覆盖 `1/2` 行。

缓存比例固定显示两位小数。输入为 0 时比例不适用；只有正输入与缓存数量在整数上完全相等，才显示 `100.00%`。任何未满比例最高显示 `99.99%`，避免极大整数经浮点或显示舍入后误报满命中。这里的“缓存命中率”来自模型用量字段；扫描器复用文件摘要的缓存命中次数不属于模型用量。

## 线程与完整轮次明细

明细显示每线程及完整轮次的输入、输出、总量、缓存读取和未缓存输入；完整轮次另显示完成时间、整轮用时和整轮均速。基础线程累计量未知时，具有独立完整证据的轮次仍可展示，不能用该轮倒推缺失的线程历史。

| 明细范围 | 上限与顺序 |
| --- | --- |
| 线程 | 最多 32 个，来自本轮已选物理文件；有可见完整轮次的线程优先 |
| 每线程完整轮次 | 保留最新 16 个，展示时按完成时间和源记录顺序升序编号 |
| 全部完整轮次 | 最多 128 个，按完成时间及确定的来源顺序选取最新记录 |

达到明细上限会明确提示；裁剪只影响明细，不改变已核验的基础小计或最新完整轮次均速。界面以“线程 N / 轮次 N”编号，不展示原始 ID、路径、正文、工具内容或账号。

这些是当前扫描快照。重复扫描整体替换，文件删除、来源切换、停止服务或退出会清除失效记录；不追加为跨重启历史，也不提供明细导出。源事件/完成时间与“本次扫描/核对时间”分别展示，读取时间不能充当模型完成时间。本地扫描仍在上一次完成后至少等待 5 秒，不保证源事件产生后立即可见。

模型调用用时、平均 TTFT 与 decode TPS 需要请求级来源事件，目前保持“未知（来源未提供）”。整轮用时、整轮均速、活动区间估算以及 Hub 金额都不能填补这些字段。

## 未知、零与未实现

- `0` 需要来源明确提供合法的零值。
- “未知”或“—”表示缺少可信来源、字段、连续事件或时效，不表示没有消耗。
- 未接通的数据不会由演示值代替。成本、请求数、失败数和响应延迟目前不是正式 Seasun App 的已完成统计能力。
- 离线预览和测试中的数字是合成数据；它们用于验证解析、布局和边界，不证明本机账号实际有这些数值。
