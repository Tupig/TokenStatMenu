# 性能与基准

[返回文档中心](wiki/Home.md)

## BP37f 当前实现边界

本轮性能改动优先解决主线程阻塞和无界更新：路由发现、Token Hub 设置/SQLite 读取与直接额度请求由 worker actor 串行执行；主 actor 只接收脱敏额度快照并用 generation 丢弃迟到结果。主线程 heartbeat、慢设置读取和重启/取消场景由合成合同覆盖。

本地历史只在菜单面板可见且有新鲜 live estimate 时采样，窗口固定为十分钟、最多 1200 点；未知和过期样本被丢弃。空闲菜单 tick 不会因为隐藏的历史图或旧代理统计反复发布相同状态。统一 `observationNow` 避免本地 freshness、直接 quota freshness 和 UI 状态在同一轮刷新中漂移。

性能检查使用固定的 A06/A07 合成输入和 A01–A09 manifest。它们测量调度、取消、边界和容量上限，不访问真实 Hub、SQLite、网络、Keychain、TCC 或用户记录。真实企业 token/s、完整历史吞吐和系统级 CPU/RSS 仍不由这些合成测量推断。

## 优化了哪些路径

1.1.1 保留 0.5 秒菜单检查、15 秒活动事件时效和本地扫描完成后至少 5 秒的采集间隔，主要减少空闲展示路径的重复工作：

| 改动 | 目的 | 验证方式 |
| --- | --- | --- |
| 本地模式不重复发布未使用的旧代理 MetricsSnapshot | 避免空闲 tick 不断使 SwiftUI 视图失效 | 合成回归统计 `objectWillChange` |
| 先判断是否有月度额度，再计算月份 | 避免无额度时创建无用的日期格式化工作 | 指定空闲菜单循环基准 |
| Tooltip 按数据/来源/时效/区域或时区变化失效 | 不在每个 tick 重新格式化全部时间和说明 | 100 次不变检查只构建 1 次，并测试新数据与时效边界 |
| 首次点击菜单栏才创建 Dashboard hosting | 菜单栏单独使用时避免预先创建整页视图 | 首次打开前创建 0 次；打开后复用同一 hosting |
| 轻量时效状态比较 | 数据未变时仍在边界更新实时、过期、历史重置说明 | 15/15.001 秒、120/120.001 秒及时间回拨回归 |

面板复用的是同一个 hosting controller，避免每次打开重建 SwiftUI 状态。创建次数回归证明了延迟创建与复用；它没有替代真实点击设置页、键盘焦点或可访问性的交互验收。

这些改动不减少数据来源、扩大缓存有效期，也不把“实时”保留超过原来的时效。Hub 直接读取和可选界面兼容读取仍分别处理权限、身份、generation 和失效。

## 可复现的合成菜单基准

从完整 Git checkout 的项目根运行：

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  python3 script/benchmark_menu.py
```

默认每个版本运行 3 轮，每轮 10,000 次 tick。快速检查工具是否正常工作可减少轮数：

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  python3 script/benchmark_menu.py --rounds 1
```

入口是 [benchmark_menu.py](../script/benchmark_menu.py)，工作负载是 [BenchmarkMenu.swift](../script/BenchmarkMenu.swift)。它们不是正常 App 启动参数，不会创建企业登录流程、读取真实配置、访问 Hub、扫描本机 Codex 记录或读取旧 `.build` 对象。

### 比较方法

| 条件 | 工具行为 |
| --- | --- |
| 基线 | 从本地 Git 提取兼容的整理前提交 `a0d7e3ef5c916d3c0159221fe6f225a337511766` 的两个菜单文件；旧 1.1.0 已不兼容当前共享视图接口 |
| 候选 | 工作区当前 `AppModel.swift` 与 `StatusBarController.swift` |
| 共用代码 | 两组均使用同一份当前 Core 和其余 App 源码，隔离菜单改动的影响 |
| 编译 | 同一 `xcrun swiftc`、同一 macOS SDK、同一主机架构 target、同一 `-Onone` 与模块参数 |
| 构建目录 | 全新临时目录，直接编译 Core、两份 App 动态库与相同 harness；结束后清理 |
| 模型 | `AppModel(preview: true)`，固定合成记录和时间，无后台服务 |
| 工作负载 | 构造状态栏 controller 后连续调用 tick，包含其菜单刷新/Tooltip 路径 |
| 计时 | 单调时钟的循环耗时，单位 ms；同时统计循环内 `objectWillChange` 次数 |
| 输出 | 每轮 JSON 与两组中位数；不持久化真实运行材料 |

controller 的创建在计时开始前，因此这组循环数据**不包含**首次 Dashboard 构造耗时，不能用它证明启动时间或内存减少了某个百分比。无真实 I/O 的连续 10,000 次循环也不等于应用正常运行 5,000 秒。

工具需要本地存在基线提交对象。从无 Git 的源码 zip 运行时无法提取基线；应使用完整 checkout。可用 `--baseline <commit>` 选择另一个本地提交，但只有两个菜单源文件会变化，且旧文件必须与当前共用代码兼容。`--rounds` 范围 1–10，`--iterations` 范围 1–1,000,000；调整参数后不能直接混入默认样本比较。

### 已记录结果的解释

在 Apple Silicon 本机使用上述公开脚本、相同编译器/SDK/`-Onone` 与默认 3 轮 × 10,000 次参数，记录为：

| 轮次 | 旧路径耗时 ms | 优化后耗时 ms |
| --- | ---: | ---: |
| 1 | 562.007 | 80.558 |
| 2 | 564.312 | 81.818 |
| 3 | 560.957 | 81.210 |
| 中位数 | 562.007 | 81.210 |

指定循环中位耗时减少约 85.6%，每轮 `objectWillChange` 从 10,000 次降到 0 次。这组结果绑定已修复“两次 tick 之间新数据到达后跨过期边界”的最终候选，描述该次合成热路径，**不是整 App CPU、能耗或 RSS 下降 85.6%**。

这些结果不构成固定耗时保证。不要将不同构建方法、单轮 smoke、编译优化级别或迭代数的结果混入本表；应以自己用相同脚本、参数、工具链和机器重复取得的结果为准。

## 正确性回归比时间阈值更稳定

原生测试覆盖以下行为，正常回归不设置绝对耗时阈值：

- 不变本地数据的 100 次 tick 不发布重复的 MetricsSnapshot。
- 活动事件在恰好 15 秒仍有效，15.001 秒失效，界面只因该边界更新一次。
- 时间回拨后重新计算活动状态，不依赖下一次文件扫描。
- 新的活动记录或历史窗口在两次 tick 之间到达、随后跨过失效/重置边界，仍发出必要的界面更新。
- Hub 快照在有效期边界仍可用，越界后菜单与 Tooltip 均移除当前窗口。
- 接近失效时间才返回的 Hub 观察，不会漏掉紧接着的失效通知。
- Tooltip 对新用量、来源切换、未来时间恢复和历史重置失效重新生成。
- 后台线程发出的区域或时区变更通知，调度到主线程使缓存失效，单次通知不造成重复格式化。
- 面板首次打开前不创建 Dashboard，随后复用 hosting。

这些检查使用合成模型、手动时钟与依赖替身，不触发真实企业请求或系统授权。运行方式见 [测试指南](wiki/测试指南.md)。

## 整 App CPU 与内存应怎样测

合成循环不能代替实际资源测量。整 App 比较应分别记录菜单栏空闲、面板首次打开、面板保持打开、持续产生新事件、Hub 重连等场景；使用相同构建配置、安装路径、采集时长与测量工具，并区分平均/峰值和 CPU 计量方式。

已记录两次菜单栏空闲短窗口观察：

| 版本 | 采样时长 | 进程 CPU 时间增量 | 单核平均 CPU | 观察到的 RSS |
| --- | ---: | ---: | ---: | ---: |
| 1.1.0 | 20.079 秒 | 0.0069 秒 | 约 0.034% | 112.08–112.25 MiB |
| 1.1.1 候选 | 20.162 秒 | 0.0044 秒 | 约 0.022% | 67.98 MiB（样本最小值与最大值相同） |

CPU 百分比由进程 CPU 时间增量除以实际采样时长计算，以一个逻辑核心为 100%。新版采样期间进程身份持续匹配固定安装候选；采样仅观察进程资源，不读取或公开企业用量数值。

这两个窗口不是受控的同年龄实例 A/B：进程已运行时长、是否首次打开过面板及其他生命周期条件没有完全统一。它们是本机短时观察，不能据此宣称整 App CPU 或内存降低了某个百分比，也不能作为长期峰值或固定资源预算。RSS 还受系统框架、共享页面、图形资源和采样时刻影响，不能由“少创建一个视图”直接算出减少量。上表与合成循环是两种独立证据，不拼接计算提升比例。

真实采样材料留在本机，公开报告仅保留脱敏的版本、场景、方法、时间范围和汇总。不要上传原始会话、真实额度、企业地址、账号、屏幕截图或运行日志。
