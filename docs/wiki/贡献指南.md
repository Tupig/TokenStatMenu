# 贡献指南

**简体中文** | [English](#contributing-english)

[文档中心](Home.md) · [测试指南](测试指南.md)

## 提交问题

先搜索 [Issues](https://github.com/Tupig/TokenStatMenu/issues)。附上版本/build、macOS、M 系列型号、来源类型、复现步骤、预期与实际结果。金额解析问题用合成数据保留字段结构，不复制真实响应。

不公开令牌、数据库、企业地址、账号、额度、会话正文、日志、证书和本机路径。截图使用合成渲染，或完整遮挡敏感内容。隐私原则见 [README](../../README.md#隐私与限制)。

## 修改代码

1. 从当前源码确认问题，较大行为改动先在 Issue 讨论。
2. 为修复补能失败的合成回归，再改实现。
3. 运行[测试指南](测试指南.md)中的相关检查；UI 另看深浅色与真实系统行为。
4. 更新中英文档和公开文件白名单。
5. PR 写明改了什么、如何验证、还有哪些限制，关联 Issue。

只支持原生 Apple 技术和 M 系列。不加入 Electron、无必要运行时或通用 API 配置。文件和网络工作离开主线程，扫描、重试和缓存保持有界；来源或 generation 变化后丢弃旧结果。

## 维护文档

文档仅放根 `README.md` 和 `docs/wiki/`。采用与 [TuPigGHD2Chinese](https://github.com/Tupig/TuPigGHD2Chinese) 一致的组织：中文在前、英文在后，顶部互链，专题页回到 Home，侧栏双语。

- 写操作、原因和结果，少写“全面赋能”“闭环”“极致”等没有信息的词。
- 命令必须能对应当前实现；未完成事项直接说明，不反复堆叠免责声明。
- 两种语言保持同一功能范围、限制和示例，不只翻译标题。
- 本地链接带 `.md`，锚点必须存在；新增公开文件加入 `script/package_source.py`。
- `Home.md` 是固定入口；仓库内文档存在不代表 GitHub Wiki 已同步。

## 公开检查

```bash
python3 -B script/check_docs.py --self-test
python3 -B script/check_public_content.py
git diff --check
```

暂存后再执行 `python3 -B script/check_public_content.py --git-index`。`.gitignore` 不会保护已跟踪文件，也不会替你检查 Issue 和截图。

## Issue 关闭条件

按实际验证关闭，不为发布清空列表。代码、系统权限、分发签名、服务端来源和自动化环境的问题分别跟踪。测试或机器不具备条件时说明阻塞，不能拿合成测试代替。

# Contributing (English)

[简体中文](#贡献指南) | **English**

[Documentation](Home.md#documentation-hub-english) · [Testing](测试指南.md#testing-guide-english)

## Reporting Issues

Search [Issues](https://github.com/Tupig/TokenStatMenu/issues) first. Include version/build, macOS, M-series model, source type, reproduction steps, expected and actual behavior. Use synthetic fields for parsing examples, never real responses.

Do not publish tokens, databases, enterprise addresses, account data, quotas, conversations, logs, certificates or local paths. Use synthetic renders or fully redact screenshots. See [README privacy notes](../../README.md#privacy-and-limitations).

## Code Changes

1. Check the current implementation; discuss larger changes in an Issue.
2. Add a failing synthetic regression before the fix.
3. Run the relevant [tests](测试指南.md#testing-guide-english), including light/dark and real-system checks for UI changes.
4. Update both languages and the public file allowlist.
5. Describe the change, verification and limitations in the PR; link the Issue.

Use native Apple technologies and M-series hardware only. Do not add Electron, unnecessary runtimes or generic API configuration. Keep I/O off the main thread and bound scans, retries and caches. Reject obsolete results after source or generation changes.

## Documentation

Keep documentation in the root `README.md` and `docs/wiki/`. Follow the organization used by [TuPigGHD2Chinese](https://github.com/Tupig/TuPigGHD2Chinese): Chinese first, English second, language links, Home navigation and a bilingual sidebar.

- Describe actions, causes and results. Avoid slogans and filler.
- Match commands to current code. State unfinished work plainly, without repeating disclaimers everywhere.
- Keep both languages equivalent in features, limitations and examples.
- Use `.md` links and valid anchors. Add public files to `script/package_source.py`.
- Keep `Home.md` as the entry point. Repository pages do not by themselves establish GitHub Wiki synchronization.

## Public Content Checks

```bash
python3 -B script/check_docs.py --self-test
python3 -B script/check_public_content.py
git diff --check
```

After staging, run `python3 -B script/check_public_content.py --git-index`. `.gitignore` does not protect tracked files or inspect Issue content and screenshots.

## Closing Issues

Close on evidence, not to empty the list before release. Track code, permissions, distribution signing, service data and automation environment separately. Record blocked checks rather than substituting synthetic results.
