# 常见问题

## 菜单栏没有出现应用

TokenStatMenu 没有主窗口，也不在 Dock 中常驻；应查看屏幕右上角的统计文字。菜单栏空间不足、刘海区域或第三方菜单栏管理器可能遮挡条目。先暂时释放菜单栏空间，再从 Finder 打开已确认路径的 App。

若曾构建多个版本，先从正在运行实例的电源按钮正常退出，再从固定安装位置打开目标版本。`pgrep` 只证明存在同名进程，不能证明它来自目标 App，也不能证明菜单栏已正确绘制。版本与源码身份的检查方法见 [编译指南](编译指南.md)。

## 5 小时或 7 天没有数据

按下面的顺序定位：

1. 看的是“Token Hub 企业额度”还是“本地额度快照”？后者仅为历史记录，不负责填补企业当前窗口。
2. Hub 是否正在运行，且自己的用量页面可以正常显示？TokenStatMenu 不代替企业登录。
3. 首次读取是否已经完成？启动后的等待状态不等于读取失败。
4. 面板给出的状态是什么？按下表处理，等待下一次自动刷新。

| 状态或现象 | 含义与处理 |
| --- | --- |
| Token Hub 未运行 | 正常打开并登录 Hub；应用会在识别其启动后重新尝试 |
| 检测到多个 Token Hub 进程 | 无法唯一确定来源；正常关闭多余实例，不要强制结束不明进程 |
| 本机登录态不可用 / 会话已过期 | 回到 Hub 完成正常登录，等待自动重读 |
| 连接配置不可用 / 地址不在受信范围 | 当前 Hub 本机连接无法安全使用；记录状态文字并提交 Issue，不公开真实连接文件 |
| 登录态交换失败 / 会话未获授权 | 现有登录会话未能完成既有后台只读交换；先确认 Hub 自身可用 |
| 后台暂时不可用 / 网络请求失败 | 检查本机网络及企业所需连接，再等待自动刷新 |
| 返回数据无法核验 / 重复额度窗口 | 后台结构或数字不符合已支持规则，需要合成字段示例或维护者进一步适配 |
| 只缺一个窗口 | 后台可能没有提供该字段；应用不会复制另一窗口来填补 |
| 界面快照已过期 | 该快照已失效，不能再当作当前额度；检查来源是否恢复 |

无需寻找一个自填 API URL 或发送 API Key。也不要为修复直接来源而重新授权辅助功能；两者独立。

## 为什么有 Token 小计，却没有实时 tok/s

累计小计可以来自较旧的记录；实时估算需要同一活动轮次中两条连续、合法且新鲜的累计事件。尚未出现第二条事件、事件停止推进超过 15 秒、当前轮次只有工具等待、记录损坏或出现读取缺口，都可能使实时值未知。

有完整历史轮次时，菜单栏改为“上轮均”；否则显示“—”。这是证据不足的状态，不应补成 `0 tok/s`。输入速率也不是上传速度。计算方式见 [统计口径](统计口径.md)。

## 为什么数字与 Codex 侧栏、Hub 或账单不同

它们覆盖范围不同：本地扫描最多 32 个物理文件，并受字节与枚举预算限制；顶层对话数不是侧栏总数，线程数不是请求数。Hub 是后台金额额度，本地是 Token 记录，两者不能直接相等。

当前 provider 与 Hub origin 的关联只描述当前配置，不能回溯证明所有历史路由。子代理、分叉、重复文件和继承证据不足的贡献也不能无条件相加。面板中的“线程”是可计算的记录，“其他线程”表示身份已发现但用量或继承信息不足；另有未识别文件和扫描限制提示。

## 要不要授权辅助功能

正常直接读取企业额度**不需要**辅助功能。可选的“Token Hub 界面兼容读取”只在直接来源不可用时作为界面来源补充，而且需要系统已经信任本应用、Hub 的额度区域可访问。

只有明确要启用该兼容方式时，才点击设置中的“请求辅助功能访问…”，按 macOS 系统设置完成授权。默认启动不会弹出授权请求。关闭兼容读取或撤销该权限不会关闭直接来源。本地开发构建身份变化后，旧授权可能不再适用；应核对实际 App 的安装路径与签名身份，不要清空系统权限数据库。

## 退出或重启 Hub 后会怎样

Hub 退出会使旧来源数据失效，应用不会继续把旧快照显示成当前数据。Hub 重新启动后会重新识别目标并自动重试直接来源。旧请求晚到、实例变化或身份不一致时，结果会被拒绝；不应靠手填地址恢复。

## 能否配置通用 API、Ollama、单价、成本或请求失败数

当前正式 App 已收敛为 Seasun Token Hub 专用工具。设置中没有通用 API、代理、模型、单价、汇率或手工月度 Token 配额。核心库保留的旧协议组件用于回归测试，不表示这些功能仍可从正式 App 启用。

没有可信来源时，不生成成本、失败请求数、延迟或服务端瞬时吞吐。新需求请先建 Issue，并说明可取得的脱敏字段结构。

## 修改了偏好却没有生效

在设置页点击“保存偏好”后才会写入；“重新加载偏好”只重读文件，不保存。刷新间隔必须是 15–3600 秒的有限数值，其他输入回到默认 60 秒。保存失败会保留原内存偏好并显示错误。

启动不会改写旧配置，旧 API 字段被忽略。主动保存只保留两项允许的偏好。若调试时使用 `--config`，确认你查看的是该隔离文件，而不是默认偏好文件。详见 [可选偏好](../CONFIGURATION.md)。

## 构建、签名或快照测试失败

| 现象 | 先检查什么 |
| --- | --- |
| 找不到 Swift、SDK 或 Xcode | `xcode-select -p` 与 `swift --version`；按 [编译指南](编译指南.md) 对当前命令指定 `DEVELOPER_DIR` |
| SwiftPM 等待另一个构建 | 同一 `.build` 目录正在被其他 SwiftPM 进程使用；等待其完成，或使用独立 scratch 路径 |
| 无法运行下载的 App | 确认来源、架构及实际签名/公证状态；本地 ad hoc 构建不等于公证发行版 |
| 快照出现像素差异 | 对照 [UI 测试说明](../UI_TESTING.md) 的 macOS、工具链和显示环境；人工审阅，不能直接覆盖基线 |
| CI 绿色但本机 UI 异常 | CI 不涵盖所有视觉、焦点、权限、真实 Hub 登录或安装验证；按 [测试指南](测试指南.md) 补做对应层次 |

## 怎样提交一个有用的问题

先搜索 [已有 Issues](https://github.com/Tupig/TokenStatMenu/issues)。新问题附上应用版本/构建号、系统版本、芯片、发生步骤、预期/实际结果和经过脱敏的状态文字。说明发生在后台直接来源、界面兼容快照还是本地记录。

不要附真实 Hub 数据库、配置、令牌、企业 URL、账号、会话正文、运行日志或原始截图。需要示例时使用虚构域名与合成数值，提交方式见 [贡献指南](贡献指南.md)。
