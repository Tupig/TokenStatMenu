## 先区分来源

| 数据 | 来源 | 单位与范围 |
| --- | --- | --- |
| 5 小时、7 天额度 | `GET /api/v1/auth/me/base-url` 明确返回 `is_direct=true` 时，读取 `GET /api/v1/auth/me/direct-key/usage` 中精确匹配的 5h、7d 窗口；明确 `is_direct=false` 时读取 routed `GET /api/v1/auth/me/quota-usage`；selector 缺失或无效时未知 | 金额、比例与各自窗口的重置时间 |

## 窗口和金额

```text
已用百分比 = 已用金额 / 窗口额度 × 100
剩余百分比 = max(0, 100 − 已用百分比)
```

窗口来源由 `GET /api/v1/auth/me/base-url` 的 `is_direct` 明确选择：`true` 时使用 `GET /api/v1/auth/me/direct-key/usage` 的 `data.subscription_usage.windows`，额度只精确识别 `5h`、`7d`，月度用量精确匹配 `30d`；`false` 时使用 routed `GET /api/v1/auth/me/quota-usage`。selector 缺失或无效时状态未知，不回退到另一来源。窗口按后台种类识别，不靠数组位置、金额大小或时间长度猜测。direct 窗口只取自身 `resets_at`；routed 窗口按自身 `reset_at`、再 `period_end`。小组件、菜单栏与面板均隐藏缺失的 5 小时窗口，不以 7 天数据补位。有限额度须大于零，已用金额须合法且非负；真实已用可超过额度，保留实际金额和大于 100% 的比例，剩余下限为零，仅进度条宽度限制在范围内。本地算术超额不代表服务端明确返回 `violated=true`。重复、歧义或无效窗口不会被修成零。

有限数值、明确不限、明确超限和未知分别表示；有效的真实零保留。`enabled=false` 的缺失、null 或零占位不生成金额或比例；明确 `violated=true` 可以在没有完整数值时表示超限。非法非空金额仍拒绝，缺失状态不当作服务端确认的 false。

菜单栏显示已用比例，面板和小组件显示剩余比例，进度条表示已用。百分比固定两位小数；后台额度以 🪙 积分固定两位显示，非负数按 half-up 舍入，千分位便于阅读。旧界面兼容来源的 `$` 保留美元单位，不把它重标为积分。积分不是美元或人民币，也不按固定比例折算 token。内部阈值使用原始值，不用显示舍入结果判断：黄色从 80% 已用起，红色从 95% 起。

月度界面有数值时显示已用金额，也可显示明确不限或超限状态；即使后台带上限，也不显示月度进度、剩余量或比例。重置时间按来源读取：direct 窗口只取自身 `resets_at`；routed 窗口取自身 `reset_at`，其次 `period_end`。不借顶层或其他窗口的时间，缺失则未知。时间按本机时区显示；不从模糊的短时间文字猜年份或时区。

上述后台字段和显示依据来自取证日 2026-11-16 的 TokenHub 4.6.13 stable 客户端静态实现，与当日[官方 stable 清单](https://tokenhub-update.ks3-cn-beijing.ksyuncs.com/channels/macos/stable/latest.json)核对版本；当前账户与官方 7 天、月度读数各两次一致，仅说明这两次观察，不泛化到所有账户或未来服务端版本。同 Team 与 App Group 的本机通道已核验；桌面 Widget 未做目视检查，系统调度也未全面验证。清单可能随版本更新。

## 时效与小组件

Hub 快照有效期为 `max(120 秒, 刷新间隔 × 2)`。未来时间、过期快照和已重置窗口不能作为当前值。Hub 退出、实例变化或旧请求晚到时会丢弃失效结果。

小组件使用同一投影生成的共享快照。首次 Hub 读取完成前不发布空快照，以免先消耗一次 WidgetKit 重载机会。之后仍受系统刷新调度约束，不承诺逐秒同步。每个窗口以及普通月度数值和月度状态均受快照时效及其自身来源重置时间约束，不会退回旧值。Widget v2 可读取 v1；旧端读取 v2 时安全降级为未知，并非双向兼容。同 Team 与 App Group 的本机通道已核验；桌面 Widget 未做目视检查，系统调度也未全面验证。

重置券只读查询当前上下文的 available 券并读取 `data.total`，不会消费券；失败或无效为未知。额度成功而券失败时保留本次额度、券数未知；额度失败时清除旧后台直读数据，不与旧券或旧额度混拼。界面兼容读取是独立标记的来源。

## 本地扫描范围

默认读取 `~/.codex/sessions` 与 `archived_sessions`；`CODEX_HOME` 可指定绝对根路径。不读取 OpenCode 会话或数据库。

| 每个目录的预算 | 上限 |
| --- | --- |
| 枚举项 | 5,000 |
| 物理文件 | 32 |
| 单文件开头 / 结尾 | 64 KiB / 256 KiB |
| 单次读取 | 10 MiB |

硬链接、归档副本和线程继承不会无条件重复相加。面板中的“线程”是可核算记录，“其他线程”表示身份已知但贡献证据不足。顶层对话数不是 Codex 侧栏总数，线程数也不是请求数。触及预算时只报告已覆盖的小计。

## 速度

活动估算要求同一轮次内两条连续、合法的累计事件：

```text
输出 tok/s ≈ 输出累计增量 / 两事件间隔
上轮均速 = 完整轮次输出增量 / 整轮时长
```

最后事件超过 15 秒后活动估算失效。不跨损坏记录、读取缺口、倒序时间或重叠轮次拼接。整轮时长包含工具、网络与等待，因此上轮均速不是纯生成速度。输入累计速率也不是上传速度或 TTFT。

服务端瞬时 token/s、请求级 TTFT 和 decode TPS 尚无权威来源，保持未知，见 [#37](https://github.com/Tupig/TokenStatMenu/issues/37)。菜单栏不再回退显示速度。

## 缓存和轮次明细

Codex 输入量已包含缓存读取，未缓存输入为 `I − C`，缓存不再加到总量中。命中率用相同有效覆盖内的 `sum(C) / sum(I)`，不平均各行比例。缺字段或无效缓存值不当作零；输入为零时比例不适用。

只有整数上确实相等才显示 `100.00%`，未满比例最高显示 `99.99%`。缓存字段与扫描器自身的文件摘要缓存是两回事。

明细最多 32 个线程、每线程最新 16 个完整轮次、合计 128 个轮次。裁剪明细不改变基础小计。界面用“线程 N / 轮次 N”，不展示原始 ID、路径或正文。记录整体替换，不累积成跨重启历史，也不提供明细导出。

## 零和未知

- `0`：来源明确提供有效零值。
- “未知”或 `—`：缺少字段、可信来源、连续事件或有效时间。
- 合成预览：只验证布局与逻辑，不代表真实账号数据。

## Windows and Amounts

```text
Used percentage = used amount / window limit × 100
Remaining percentage = max(0, 100 − used percentage)
```

`is_direct` from `GET /api/v1/auth/me/base-url` explicitly selects the source: `true` uses `data.subscription_usage.windows` from `GET /api/v1/auth/me/direct-key/usage`, with quota windows matching exact `5h` and `7d` and monthly usage matching exact `30d`; `false` uses routed `GET /api/v1/auth/me/quota-usage`. A missing or invalid selector stays unknown and does not fall back to the other source. Window types come from explicit service fields, not array order, amount size or guessed duration. Direct windows use only their own `resets_at`; routed windows use their own `reset_at`, then `period_end`. The widget, menu bar and panel all hide a missing five-hour window instead of borrowing seven-day data. Finite limits must be positive and usage valid and non-negative. Actual usage may exceed the limit: the amount and percentage above 100% are retained, remaining is floored at zero, and only bar width is clamped. Local arithmetic excess does not assert that the service returned `violated=true`. Duplicate, ambiguous or invalid windows are not repaired with zero.

Finite numeric values, explicit unlimited, explicit exceeded and unknown are distinct; an actual valid zero is retained. Missing, null or zero placeholders with `enabled=false` do not produce an amount or percentage. Explicit `violated=true` can represent exceeded without complete numeric values. Invalid non-empty amounts are still rejected; a missing flag is not a service-confirmed false.

The menu bar shows used percentages; the panel and widget show remaining percentages, with bars indicating used. Percentages use two decimals; direct Hub amounts use 🪙 credits with exactly two decimals and positive half-up rounding. A legacy `$` UI compatibility source retains dollars and is not relabeled as credits. Credits are not USD or RMB and are not converted to a fixed token quantity. Thresholds use raw values: yellow at 80% used, red at 95%, without display-rounding effects.

Monthly UI shows the used amount when numeric data is available, and may instead show an explicit unlimited or exceeded state. It shows no monthly bar, remaining amount or percentage, even if the service supplies a limit. Reset time follows the source: a direct window uses only its own `resets_at`; a routed window uses its own `reset_at`, then `period_end`. It never borrows a top-level or sibling-window time, and a missing time stays unknown. Times use local time; ambiguous short UI text does not establish a year or timezone.

These service fields and display rules derive from static analysis of the TokenHub 4.6.13 stable client on 2026-11-16, with its version checked against the [official stable manifest](https://tokenhub-update.ks3-cn-beijing.ksyuncs.com/channels/macos/stable/latest.json). The current account matched the official seven-day and monthly readings twice each; these observations do not generalize to all accounts or future server versions. The local same-Team and App Group channel was verified; the desktop Widget was not visually inspected, and system scheduling was not fully verified. The manifest may change with future releases.

## Freshness and Widget

Hub snapshots remain valid for `max(120 seconds, refresh interval × 2)`. Future, expired or reset values cannot be current. Hub exit, identity changes and late obsolete responses invalidate results.

The widget receives a snapshot from the same presentation projection. No empty snapshot is published before the first Hub read, avoiding an early reload that would delay the useful result. WidgetKit still schedules refreshes; second-by-second synchronization is not promised. Each window, normal monthly numeric value and monthly state obeys snapshot freshness and its own source reset time, without reverting to older values. Widget v2 reads v1; an old reader safely treats v2 as unknown, so compatibility is not bidirectional. The local same-Team and App Group channel was verified; the desktop Widget was not visually inspected, and system scheduling was not fully verified.

The read-only voucher query counts available vouchers in the current context via `data.total`; it does not consume them. Failure or invalid data is unknown. If quota succeeds but vouchers fail, the current quota remains and voucher count is unknown. If quota fails, old direct data is cleared instead of combining old vouchers or quota with a new result. UI compatibility data is a separately labeled source.

## Local Scan Coverage

The default roots are `~/.codex/sessions` and `archived_sessions`; `CODEX_HOME` may provide an absolute root. OpenCode sessions and databases are not read.

| Budget per directory | Limit |
| --- | --- |
| Enumerated entries | 5,000 |
| Physical files | 32 |
| File head / tail | 64 KiB / 256 KiB |
| Total read per scan | 10 MiB |

Hard links, archives and inherited thread usage are not blindly counted twice. Threads are accountable records; other threads have known identity but insufficient contribution evidence. Top-level conversations are not the complete Codex sidebar, and threads are not requests. Budget limits produce a covered subtotal, not a full-account total.

## Rates

Activity estimation needs two consecutive, valid cumulative events in the same turn:

```text
Output tok/s ≈ output delta / interval between events
Completed-turn average = turn output delta / full turn duration
```

Activity estimates expire after 15 seconds without a new event. Corrupt records, gaps, reversed time and overlapping turns break the chain. Full-turn duration includes tools, network and waits; input progression is not upload speed or TTFT.

Authoritative server token/s, request-level TTFT and decode TPS are unavailable; see [#37](https://github.com/Tupig/TokenStatMenu/issues/37). The menu bar no longer falls back to a rate title.

## Cache and Turn Details

Codex input includes cached input. Uncached input is `I − C`; cached input is not added to the total again. Hit rate is `sum(C) / sum(I)` over matching valid coverage, not the mean of row percentages. Missing or invalid cache values stay unknown; a zero input has no applicable ratio.

Only exact integer equality yields `100.00%`; incomplete ratios are capped at `99.99%` for display. Model cache usage is separate from the scanner's file-summary cache.

Details are limited to 32 threads, the latest 16 completed turns per thread and 128 turns overall. Trimming details does not change base subtotals. The UI uses numbered thread/turn labels, not raw IDs, paths or text. Records are replaced as a snapshot, not kept as cross-restart history or exported.

## Zero and Unknown

- `0`: an explicit valid zero from the source.
- Unknown or `—`: insufficient fields, source confidence, event continuity or freshness.
- Synthetic previews: layout and logic examples, not real account data.
