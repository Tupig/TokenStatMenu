## 本地回归

在 M 系列 Mac 上使用完整 Xcode：

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
swift run --force-resolved-versions TokenStatCoreChecks
swift test --force-resolved-versions
TOKENSTAT_SKIP_BUILD_BUMP=1 ./script/test.sh
python3 -B script/test_release_assets.py
python3 -B script/check_docs.py --self-test
python3 -B script/check_public_content.py
git diff --check
```

同一 `.build` 不要并发运行 SwiftPM 命令。依赖锁若发生变化，先查原因，不能靠删除或恢复文件掩盖。`script/test.sh` 的子进程使用临时偏好且关闭后台服务，不访问真实 Hub。

| 检查 | 验证范围 |
| --- | --- |
| CoreChecks | 合成解析、金额、窗口、核算与重置券 |
| `swift test` | App 状态、生命周期、共享存储与 UI 回归 |
| `script/test.sh` | 核心、App 构建、隔离启动与保存/重载 |
| Release 测试 | 版本、路径、摘要、签名和镜像包装的正反夹具 |
| 文档检查 | 白名单文档的本地链接与锚点 |
| 公开内容检查 | 工作区或暂存 blob 中的文件及敏感内容规则 |

## 图像测试

```bash
swift test --force-resolved-versions --filter TokenStatUISnapshotTests
python3 -B script/render_preview.py
```

检查浅色/深色、金额换行、截断、按钮对称、未知和过期状态。正式面板为 300×420 点；小组件只保留 small，文字统一 10pt。预览使用合成数据，输出到被忽略的 `dist/previews/`。

需要接受视觉改动时，先看差异，再显式录制：

```bash
TOKENSTAT_RECORD_SNAPSHOTS=1 swift test --force-resolved-versions --filter TokenStatUISnapshotTests
swift test --force-resolved-versions --filter TokenStatUISnapshotTests
```

录制测试会按设计报告失败；第二次不带变量的测试才是回归结果。不要把真实账户截图存为基线。OCR、离屏渲染和原生辅助功能树是不同检查；[#33](https://github.com/Tupig/TokenStatMenu/issues/33) 的自动化环境阻塞不能靠 OCR 通过关闭。

## 小组件检查

共享层测试应覆盖金额字段向后兼容、零/未知重置券、过期边界、未来时间、窗口重置、写入失败与重载节流。App 启动前的空状态不抢占首次有效发布；成功后的断连必须清空旧值。

开发候选另有无签名、无 App 宿主的原生产品 XCTest（测试运行需 macOS 14 或更高，产品最低版本不变）：

开发候选不主动调用 WidgetKit reload；刷新检查针对真实 Provider 的 `.after(当前时间 + 300秒)` 请求策略和到期时间线，不声称实际 reload 节流或系统准点调度。

```bash
xcodebuild -project TokenStatMenu.xcodeproj -scheme TokenStatDevWidgetLogicTests \
  -destination 'platform=macOS,arch=arm64' -derivedDataPath .build/dev-widget-logic \
  -parallel-testing-enabled NO CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO test
```

该目标直接编译真实早入口、Store 和 Provider，以虚构身份及临时目录验证拒绝路径、两代读写、受控提交竞态和过期时间线。它不查询真实签名或共享容器，不证明系统授权成功，也不保证 WidgetKit 在请求时间准点刷新。中文图像标签允许原始 OCR 候选及多尺度行区域重识别，后者启用系统语言纠正但不注入预期词；数值和旧值泄露仍检查未经语言纠正的整图首选结果，不能据此宣称中文字形或原生辅助功能验收通过。

部分 macOS 的 Vision 将“重置券”稳定识别为“重置劵”。这一处图像歧义仅在实际视图使用的同一个 `Text` 精确等于“重置券”时接受；判定器的反例覆盖错误产品文案、空文案及缺失 OCR 标签，不冒称实际移除标题的渲染负测。不替换整图文字，也不放宽金额或券数检查。

在有授权的开发签名版本上，另行检查真实图库添加、四项数据、字号、重启恢复和到期变化。文件可读或合成图正确，都不能代替系统 Widget 验收。公开 ad hoc 包的 App Group 限制见 [#88](https://github.com/Tupig/TokenStatMenu/issues/88)。

## 安装与更新检查

发布后从公开 Release 下载，不复用本地缓存产物：

1. 确认 Release 非草稿，版本为 1.1.8，五项资产齐全。
2. 核对 manifest 与 SHA256SUMS；只读挂载 `TokenStatMenu.dmg`，检查 App、架构、版本和签名。
3. 确认安装后的 App 来自目标路径，不是还在运行的旧副本。
4. Tap 测试通过并更新配方后，运行 `brew update`、`brew upgrade` 与 `brew test`。
5. 检查新安装与已有安装的升级；保留个人偏好和手动副本，不自动杀用户进程。

`brew test` 验证 Bundle、arm64、来源、签名与启动器，不启动 GUI。真实 Hub 登录、菜单栏和 Widget 需要另外检查。

## 提交前

```bash
python3 -B script/package_source.py
python3 -B script/check_public_content.py --git-index
```

暂存后再检查精确内容。报告写实际命令、退出码和未完成项；不把旧测试数字、CI 绿灯或可挂载 DMG 写成全部验收通过。

## Local Regressions

Use full Xcode on an M-series Mac:

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
swift run --force-resolved-versions TokenStatCoreChecks
swift test --force-resolved-versions
TOKENSTAT_SKIP_BUILD_BUMP=1 ./script/test.sh
python3 -B script/test_release_assets.py
python3 -B script/check_docs.py --self-test
python3 -B script/check_public_content.py
git diff --check
```

Do not run concurrent SwiftPM commands in one `.build`. Investigate lock changes rather than deleting or restoring them to conceal a failure. Integration subprocesses use temporary preferences with background services disabled.

| Check | Coverage |
| --- | --- |
| CoreChecks | Synthetic parsing, amounts, windows, accounting and vouchers |
| `swift test` | App state, lifecycle, shared storage and UI regressions |
| `script/test.sh` | Core, App assembly, isolated launch and preference reload |
| Release tests | Positive and rejection fixtures for identity, paths, digests, signing and images |
| Documentation checks | Local links and anchors in allowlisted pages |
| Public content checks | Worktree or staged file/content rules |

## Image Tests

```bash
swift test --force-resolved-versions --filter TokenStatUISnapshotTests
python3 -B script/render_preview.py
```

Review light/dark appearance, amount wrapping, truncation, button symmetry and unknown/expired states. The panel is 300×420 points. The widget is small only with 10pt text. Synthetic previews go into ignored `dist/previews/`.

Review a visual change before explicitly recording references:

```bash
TOKENSTAT_RECORD_SNAPSHOTS=1 swift test --force-resolved-versions --filter TokenStatUISnapshotTests
swift test --force-resolved-versions --filter TokenStatUISnapshotTests
```

Recording reports failures by design. The second run, without recording, is the regression result. Never store real account screenshots as references. OCR, offscreen rendering and native Accessibility trees are separate checks. Do not close [#33](https://github.com/Tupig/TokenStatMenu/issues/33) based on OCR while native automation remains blocked.

## Widget Checks

Shared tests cover old-snapshot compatibility, voucher zero/unknown, expiration, future time, window resets, write failures and reload throttling. Initial loading must not consume the first useful publication; later disconnection must invalidate old values.

The development candidate also has unsigned, hostless native product XCTest tests (macOS 14 or later for the test runner; product minimum versions are unchanged):

The development candidate does not actively call WidgetKit reload. Refresh checks cover the actual Provider's `.after(now + 300 seconds)` request policy and expiry entries, not active reload throttling or punctual system scheduling.

```bash
xcodebuild -project TokenStatMenu.xcodeproj -scheme TokenStatDevWidgetLogicTests \
  -destination 'platform=macOS,arch=arm64' -derivedDataPath .build/dev-widget-logic \
  -parallel-testing-enabled NO CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO test
```

This target compiles the actual early runner, Store and Provider. Fictional identities and temporary directories exercise rejection, two-generation reads/writes, a controlled commit race and expiry timelines. It does not query real signing or shared containers, establish system authorization, or guarantee punctual WidgetKit refresh. Chinese image labels accept raw OCR candidates and multiscale line-region recognition, with system language correction but no injected expected words for the latter. Numeric values and stale-value leakage still use the full-image top result without language correction. This does not establish exact glyph or native Accessibility acceptance.

On some macOS versions, Vision consistently reads `重置券` as `重置劵`. This image ambiguity is accepted only when the same `Text` used by the actual view exactly equals `重置券`. Oracle rejection tests cover incorrect product text, empty text and missing OCR labels; they do not claim to render a view with the title removed. Full-image text, amount checks and voucher-count checks are not rewritten or relaxed.

An authorized development build also needs real gallery, layout, restart and expiry checks. A readable file or synthetic render is not system Widget acceptance. See [#88](https://github.com/Tupig/TokenStatMenu/issues/88) for public ad hoc limitations.

## Installation and Upgrade

Download from the public Release rather than reusing local artifacts:

1. Confirm a non-draft 1.1.8 Release and all five assets.
2. Verify manifest and SHA256SUMS. Mount `TokenStatMenu.dmg` read-only; check the App, architecture, version and signature.
3. Check that the installed copy is the one running, not an old process.
4. After Tap tests and formula publication, run `brew update`, `brew upgrade` and `brew test`.
5. Test fresh installation and an existing-install upgrade while preserving preferences and manual copies, without killing user processes.

`brew test` validates the Bundle, arm64, source identity, signing and launcher. It does not launch the GUI or establish Hub/Widget functionality.

## Before Committing

```bash
python3 -B script/package_source.py
python3 -B script/check_public_content.py --git-index
```

Check exact staged content after staging. Report commands, exit codes and outstanding checks. Old test counts, green CI and a mountable DMG are not complete acceptance.
