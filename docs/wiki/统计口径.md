## 先区分来源

| 数据 | 来源 | 单位与范围 |
| --- | --- | --- |
| 5 小时、7 天额度 | Hub 后台明确标识的窗口 | 金额、比例与重置时间 |
| 月度用量 | Hub 月度已用字段 | 后台提供的金额，不是本地 Token 折算 |
| 重置券 | 重置券接口 `data.total` | 数量；失败或字段无效时未知 |
| 本地用量 | 与当前 provider 关联的 Codex 记录 | 有界扫描中的 Token 小计 |
| 活动估算、上轮均速 | 本地累计事件与完整轮次 | tok/s，不是服务端瞬时速度 |
| 界面兼容快照 | Hub 可访问界面 | 明确标为“界面”，不冒充后台来源 |

本地 Token、企业金额和完整账户账单不能互相替代。当前 provider 与 Hub origin 关联，也不能证明所有历史会话过去都经过同一网关。

## 窗口和金额

```text
已用百分比 = 已用金额 / 窗口额度 × 100
剩余百分比 = 100 − 已用百分比
```

窗口按后台种类识别，不靠数组位置、金额大小或时间长度猜测。额度须大于零，已用金额须合法、非负且不超过额度。重复、歧义或无效窗口不会被修成零；缺失的 5 小时窗口也不会借用 7 天数据。

菜单栏显示已用比例，面板和小组件显示剩余比例，进度条表示已用。百分比固定两位小数；金额最多两位，月度固定两位，千分位便于阅读。内部阈值使用原始值，不用显示舍入结果判断：黄色从 80% 已用起，红色从 95% 起。

月度界面只显示已用金额，即使后台带上限，也不显示月度进度、剩余量或比例。重置时间按本机时区显示；不从模糊的短时间文字猜年份或时区。

## 时效与小组件

Hub 快照有效期为 `max(120 秒, 刷新间隔 × 2)`。未来时间、过期快照和已重置窗口不能作为当前值。Hub 退出、实例变化或旧请求晚到时会丢弃失效结果。

小组件使用同一投影生成的共享快照。首次 Hub 读取完成前不发布空快照，以免先消耗一次 WidgetKit 重载机会。之后仍受系统刷新调度约束，不承诺逐秒同步。每个窗口独立失效，不会退回旧值。

## 本地扫描范围

默认读取 `~/.codex/sessions` 与 `archived_sessions`；`CODEX_HOME` 可指定绝对根路径。不读取 OpenCode 会话或数据库。

| 每个目录的预算 | 上限 |
| --- | --- |
| 枚举项 | 5,000 |
| 物理文件 | 32 |
| 单文件开头 / 结尾 | 64 KiB / 256 KiB |
| 单次读取 | 10 MiB |

硬链接、归档副本和线程继承不会无条件重复相加。面板中的“线程”是可核算记录，“其他线程”表示身份已知但贡献证据不足。顶层对话数不是 Codex 侧栏总数，线程数也不是请求数。触及预算时只报告已覆盖的小计。

## 速度

活动估算要求同一轮次内两条连续、合法的累计事件：

```text
输出 tok/s ≈ 输出累计增量 / 两事件间隔
上轮均速 = 完整轮次输出增量 / 整轮时长
```

最后事件超过 15 秒后活动估算失效。不跨损坏记录、读取缺口、倒序时间或重叠轮次拼接。整轮时长包含工具、网络与等待，因此上轮均速不是纯生成速度。输入累计速率也不是上传速度或 TTFT。

服务端瞬时 token/s、请求级 TTFT 和 decode TPS 尚无权威来源，保持未知，见 [#37](https://github.com/Tupig/TokenStatMenu/issues/37)。菜单栏不再回退显示速度。

## 缓存和轮次明细

Codex 输入量已包含缓存读取，未缓存输入为 `I − C`，缓存不再加到总量中。命中率用相同有效覆盖内的 `sum(C) / sum(I)`，不平均各行比例。缺字段或无效缓存值不当作零；输入为零时比例不适用。

只有整数上确实相等才显示 `100.00%`，未满比例最高显示 `99.99%`。缓存字段与扫描器自身的文件摘要缓存是两回事。

明细最多 32 个线程、每线程最新 16 个完整轮次、合计 128 个轮次。裁剪明细不改变基础小计。界面用“线程 N / 轮次 N”，不展示原始 ID、路径或正文。记录整体替换，不累积成跨重启历史，也不提供明细导出。

## 零和未知

- `0`：来源明确提供有效零值。
- “未知”或 `—`：缺少字段、可信来源、连续事件或有效时间。
- 合成预览：只验证布局与逻辑，不代表真实账号数据。

## Sources

| Data | Source | Unit and coverage |
| --- | --- | --- |
| Five-hour and seven-day quotas | Explicit Hub service windows | Amounts, percentages and reset times |
| Monthly spend | Hub monthly used field | Service amount, not a local Token conversion |
| Reset vouchers | Voucher response `data.total` | Count; unknown on failure or invalid data |
| Local usage | Codex records associated with the current provider | Token subtotal within bounded scans |
| Activity and completed-turn rates | Local cumulative events and completed turns | tok/s, not server instantaneous throughput |
| UI compatibility snapshot | Accessible Hub interface | Labeled as UI data, not direct service data |

Local Tokens, enterprise amounts and the complete account bill are different measures. A current provider-to-origin match does not establish historical routing for every session.

## Windows and Amounts

```text
Used percentage = used amount / window limit × 100
Remaining percentage = 100 − used percentage
```

Window types come from explicit service fields, not array order, amount size or guessed duration. Limits must be positive; usage must be valid, non-negative and within the limit. Duplicate, ambiguous or invalid windows are not repaired with zero. A missing five-hour window never borrows seven-day data.

The menu bar shows used percentages; the panel and widget show remaining percentages, with bars indicating used. Percentages use two decimals; amounts use up to two, monthly spend exactly two. Thresholds use raw values: yellow at 80% used, red at 95%, without display-rounding effects.

Monthly UI shows used amount only, even if the service supplies a limit. No monthly bar, remaining amount or percentage is shown. Reset times use local time; ambiguous short UI text does not establish a year or timezone.

## Freshness and Widget

Hub snapshots remain valid for `max(120 seconds, refresh interval × 2)`. Future, expired or reset values cannot be current. Hub exit, identity changes and late obsolete responses invalidate results.

The widget receives a snapshot from the same presentation projection. No empty snapshot is published before the first Hub read, avoiding an early reload that would delay the useful result. WidgetKit still schedules refreshes; second-by-second synchronization is not promised. Windows expire independently without reverting to older values.

## Local Scan Coverage

The default roots are `~/.codex/sessions` and `archived_sessions`; `CODEX_HOME` may provide an absolute root. OpenCode sessions and databases are not read.

| Budget per directory | Limit |
| --- | --- |
| Enumerated entries | 5,000 |
| Physical files | 32 |
| File head / tail | 64 KiB / 256 KiB |
| Total read per scan | 10 MiB |

Hard links, archives and inherited thread usage are not blindly counted twice. Threads are accountable records; other threads have known identity but insufficient contribution evidence. Top-level conversations are not the complete Codex sidebar, and threads are not requests. Budget limits produce a covered subtotal, not a full-account total.

## Rates

Activity estimation needs two consecutive, valid cumulative events in the same turn:

```text
Output tok/s ≈ output delta / interval between events
Completed-turn average = turn output delta / full turn duration
```

Activity estimates expire after 15 seconds without a new event. Corrupt records, gaps, reversed time and overlapping turns break the chain. Full-turn duration includes tools, network and waits; input progression is not upload speed or TTFT.

Authoritative server token/s, request-level TTFT and decode TPS are unavailable; see [#37](https://github.com/Tupig/TokenStatMenu/issues/37). The menu bar no longer falls back to a rate title.

## Cache and Turn Details

Codex input includes cached input. Uncached input is `I − C`; cached input is not added to the total again. Hit rate is `sum(C) / sum(I)` over matching valid coverage, not the mean of row percentages. Missing or invalid cache values stay unknown; a zero input has no applicable ratio.

Only exact integer equality yields `100.00%`; incomplete ratios are capped at `99.99%` for display. Model cache usage is separate from the scanner's file-summary cache.

Details are limited to 32 threads, the latest 16 completed turns per thread and 128 turns overall. Trimming details does not change base subtotals. The UI uses numbered thread/turn labels, not raw IDs, paths or text. Records are replaced as a snapshot, not kept as cross-restart history or exported.

## Zero and Unknown

- `0`: an explicit valid zero from the source.
- Unknown or `—`: insufficient fields, source confidence, event continuity or freshness.
- Synthetic previews: layout and logic examples, not real account data.
