# 编译指南

## 环境与工程入口

项目最低部署目标为 macOS 13，Swift Package 使用 Swift tools 5.9。正式目标只使用系统框架，支持 Apple Silicon 和 Intel；SnapshotTesting 是测试目标的依赖，不进入正式 App。

```bash
git clone https://github.com/Tupig/TokenStatMenu.git
cd TokenStatMenu
xcode-select -p
swift --version
```

仓库同时提供 `Package.swift` 与 `TokenStatMenu.xcodeproj`。SwiftPM 命令使用工具链默认构建系统，无需额外传入旧的 native 模式参数。使用 SwiftPM 可构建可执行文件，构建脚本进一步组装原生 `.app`；Xcode 工程用于图形化编辑、调试与原生构建。

若需要完整 Xcode，而系统默认目录指向 Command Line Tools，可只给当前命令选择工具链：

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift --version
```

下文命令中的 Xcode 路径是常见安装位置，若应用名或位置不同，应替换为实际位置；不要求修改全局开发目录。

## CLT 默认构建的已知工具链警告

Swift 6.4 / Command Line Tools 27.0 的默认 SwiftBuild 引擎可能为 CLT 添加不存在的 `Developer/usr/lib` 与 `Developer/Library/Frameworks` 搜索路径，产生非致命 linker warning。这些 warning 不表示编译失败：本项目已验证 CLT 默认构建成功，但警告仍在。

本机用无依赖 Hello 包独立复现了相同警告；最小环境冷构建仍会出现，完整 Xcode 对照和直接 `swiftc` 编译则没有这两条警告。上游跟踪见 [SwiftPM #10557](https://github.com/swiftlang/swift-package-manager/issues/10557)，本项目跟踪见 [#52](https://github.com/Tupig/TokenStatMenu/issues/52)。

安装完整 Xcode 时，可仅为当前构建选择它；以下命令已验证能完成构建，并避开这组 CLT 搜索路径警告：

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer ./script/build_and_run.sh --build-only
```

此命令不改变全局 `xcode-select`。保留默认构建引擎及真实诊断，等待上游修复后复验；CLT 警告尚未消除，本项目 Issue 保持开放。

## 构建一个本机 App

```bash
./script/build_and_run.sh --build-only
open dist/TokenStatMenu.app
```

`--build-only` 生成当前架构的 Debug App，并停止于构建，不关闭用户应用或自动运行。脚本复制二进制、`Resources/Info.plist` 及原生 `Resources/AppIcon.icns`，写入公开源码身份后作本地 ad hoc 签名。当前版本元数据为 1.1.2（build 4）；实际产物仍应按下面的命令核对。

只需要 Release 可执行文件时：

```bash
swift build -c release --product TokenStatMenu
swift build -c release --show-bin-path
```

这两个 SwiftPM 命令不会自动组装 `.app`。脚本的 `--release` 模式则是“构建 Release App **并启动**”，不能把它当作只构建或隔离验证选项。

## 构建 Universal App

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  ./script/build_and_run.sh --universal
lipo -info dist/TokenStatMenu.app/Contents/MacOS/TokenStatMenu
codesign --verify --deep --strict dist/TokenStatMenu.app
```

该模式分别以 Release 构建 `arm64` 和 `x86_64`，通过 `lipo` 合并到同一 App，不启动。产物位于 `dist/TokenStatMenu.app`；`dist/` 与各架构的 `.build` 中间产物均被 Git 忽略。检查到两个架构说明二进制包含两种架构，不等于已经在 Intel 实机完成验收。

## 在 Xcode 中构建与调试

```bash
open TokenStatMenu.xcodeproj
```

工程包含由生成器维护的[共享 TokenStatMenu Scheme](../../TokenStatMenu.xcodeproj/xcshareddata/xcschemes/TokenStatMenu.xcscheme)，直接绑定既有 App target；`script/generate_xcode_project.py` 会同时重建工程与共享 Scheme。选择 `TokenStatMenu` Scheme 与 `My Mac`，使用 Build 构建、Run 运行。运行后从菜单栏打开面板；没有主窗口是预期行为。Xcode 跑起的一份 App 和固定安装目录中的 App 可能来自不同路径，调试时应避免同时运行多个版本。

命令行只构建 Xcode Release：

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild \
  -project TokenStatMenu.xcodeproj \
  -scheme TokenStatMenu \
  -configuration Release \
  -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath /tmp/TokenStatMenu-Xcode \
  build
```

Intel 主机应按其目标架构调整 destination。Xcode 的 DerivedData 产物与脚本的 `dist/` 是不同目录，不要把其中一份的验证套用于另一份。

## 核对版本与源码身份

```bash
/usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' dist/TokenStatMenu.app/Contents/Info.plist
/usr/libexec/PlistBuddy -c 'Print :CFBundleVersion' dist/TokenStatMenu.app/Contents/Info.plist
/usr/libexec/PlistBuddy -c 'Print :TokenStatSourceRevision' dist/TokenStatMenu.app/Contents/Info.plist
/usr/libexec/PlistBuddy -c 'Print :TokenStatSourceState' dist/TokenStatMenu.app/Contents/Info.plist
```

前两项来自版本元数据；后两项由构建脚本写入。`clean` 表示构建时该仓库工作区干净，`modified` 表示有改动；从不包含 Git 的源码包构建时使用 `source-export` / `unspecified`，不冒用解压路径外另一仓库的 revision。这些字段不包含本机路径、主机名、账号或企业地址。

源码身份有助于追踪，但不能单独证明运行实例就是这份产物。安装验收还需要确认实际启动路径、二进制及数据就绪情况，见 [测试指南](测试指南.md)。

## 签名与分发范围

构建脚本的 `codesign --sign -` 是本地 ad hoc 签名，不是 Developer ID 签名。`codesign --verify` 成功只说明签名结构检查通过，不代表 Apple 公证、下载后的 Gatekeeper 验证或企业安全策略验收完成。

当前 CI 没有配置证书、公证凭据或自动 Release。正式对外分发前，需要独立准备证书与公证流程，核对版本、架构、签名、来源清单、产物摘要和安装后行为。不要把证书、密码、企业配置或真实运行数据加入仓库。

## 重建原生应用图标

应用图标是项目原创的 Swift 几何绘制资源，使用蓝紫底色、白色脉冲与 Token 圆点。最终资源不依赖生成式图片服务或额外运行时框架。

```bash
./script/make_app_icon.sh
```

脚本通过 [RenderAppIcon.swift](../../script/RenderAppIcon.swift) 从零绘制 1024 × 1024 的 [AppIcon.png](../../Resources/AppIcon.png)，使用系统 `sips` 生成各尺寸，再由 `iconutil` 生成 [AppIcon.icns](../../Resources/AppIcon.icns)。`.iconset` 中间文件位于 `.build/`。修改源绘制后应检查透明边缘和小尺寸清晰度，再构建 App；SwiftPM App 组装脚本与 Xcode 资源阶段均包含 `.icns`。
