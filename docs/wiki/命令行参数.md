# 命令行参数

[返回文档中心](Home.md)

普通用户直接打开 App 即可。这里主要面向开发、隔离验证与维护，须区分“App 参数”“构建脚本模式”和“离线工具参数”；它们不是同一套解析器。

## 正式 App 识别的参数

参数由 App 自己读取，可直接传给 `Contents/MacOS/TokenStatMenu`，也可通过 `open … --args` 传入。当前没有统一的 `--help` 页面或通用参数校验，不能根据名字推断未列出的功能。

| 参数 | 值 | 实际行为 |
| --- | --- | --- |
| `--config <path>` | 偏好文件路径 | 改变本应用偏好位置；不存在的文件使用默认偏好，启动不自动创建 |
| `--show-panel` | 无 | 启动后约 0.5 秒打开面板，仅用于显式检查；正常启动不会打开 |
| `--request-accessibility` | 无 | 显式调用可选兼容读取的授权入口；不是企业后台直接读取的前提 |
| `--disable-background-services` | 无 | 关闭后台服务，供隔离验证；不会取得真实统计 |
| `--diagnostics-output <path>` | 输出 JSON 路径 | 将就绪布尔值、来源状态和后台资源计数写到本机文件；不导出 Token、额度、凭据或会话正文 |
| `--test-fixture` | 无 | 标记测试数据语义，并抑制原生辅助功能扫描；**单独使用不能隔离所有后台 I/O** |

`--config` 与 `--diagnostics-output` 必须有下一项值。开发时建议使用绝对路径并正确引用含空格的路径。不要把真实企业配置复制到仓库中，也不要把测试诊断当作统计数据源。

仅打开面板的例子：

```bash
open dist/TokenStatMenu.app --args --show-panel
```

隔离启动示例使用临时目录，不会读取真实统计：

```bash
TEST_DIRECTORY=$(mktemp -d)
dist/TokenStatMenu.app/Contents/MacOS/TokenStatMenu \
  --config "$TEST_DIRECTORY/config.plist" \
  --disable-background-services \
  --diagnostics-output "$TEST_DIRECTORY/readiness.json" \
  --show-panel
```

这个例子前台运行 App，正常从面板退出后命令结束；不要把它当作默认自动接入测试。隔离回归应优先使用已有的 `./script/test.sh`，由脚本管理自己的子进程与临时文件。

## 构建脚本模式

`script/build_and_run.sh` 只读取第一个位置参数作为模式，当前没有叠加模式或将任意尾随参数转发给 App 的机制。构建与测试脚本采用 SwiftPM 默认构建系统；无需额外选择旧 native 模式。

| 调用 | 构建 | 后续行为 |
| --- | --- | --- |
| 无参数或 `run` | 当前架构 Debug App | 使用 `open -n` 启动 |
| `--build-only` | 当前架构 Debug App | 构建后退出，不启动 |
| `--universal` | arm64 + x86_64 Release App | 合并签名后退出，不启动 |
| `--release` | 当前架构 Release App | 启动 |
| `--verify` | 当前架构 Debug App | 启动后作同名进程存在性检查；不是 UI 或安装路径验证 |
| `--debug` | 当前架构 Debug App | 交给 LLDB |
| `--logs` 或 `--telemetry` | 当前架构 Debug App | 启动后进入本机统一日志流；不是上传遥测 |

除只构建模式外，多次调用可能新开实例；开发者应先确认已有运行实例。构建脚本不会按进程名批量关闭用户 App。运行日志可能包含环境信息，不作为公开 Issue 附件。

## 离线渲染与源码工具

| 工具 | 参数 | 说明 |
| --- | --- | --- |
| `python3 script/render_preview.py` | 无 | 编译并运行专用离线渲染器，将合成预览放入 `dist/previews/` |
| 同上 | `--focus-diagnostic` | 生成专用焦点检查材料；不表示自然键盘焦点已验证 |
| `python3 script/package_source.py` | 无 | 按显式白名单生成 `dist/TokenStatMenu-source.zip`；默认不改写跟踪文件 |
| 同上 | `--export <directory>` | 额外复制白名单到新建或空目录；拒绝覆盖非空目录 |
| `python3 script/check_public_content.py` | 无 | 检查当前工作区白名单内容 |
| 同上 | `--git-index` | 检查精确暂存 blob |
| `python3 script/check_docs.py` | 无 / `--self-test` | 检查仓库 Markdown 的本地链接和锚点；后者同时执行检查器合成回归 |
| `python3 script/benchmark_menu.py` | 默认 3 轮 × 10,000 次；可设 `--rounds` / `--iterations` / `--baseline` | 隔离编译、对比合成菜单路径，方法与边界见 [性能与基准](../PERFORMANCE.md) |

离线渲染器内部也使用 `--test-fixture` 和输出路径，但它是单独编译的工具，不能把其位置参数当作正式 App 的导出功能。它的合成历史核心状态不启动正式通用代理接入。

## 环境变量

| 环境变量 | 使用场景 | 边界 |
| --- | --- | --- |
| `DEVELOPER_DIR` | 为当前命令选择 Xcode | 构建工具链选择，不是企业连接配置 |
| `CODEX_HOME` | 本地 Codex 配置与 `sessions` 根目录 | 只有绝对路径才作为自定义根使用；正式环境需从启动进程继承，Finder 启动不一定继承终端设置 |
| `TOKENSTAT_RECORD_SNAPSHOTS=1` | 显式重新录制 UI 测试基线 | 仅用于审阅后接受基线，正常回归不要设置；详见 [UI 测试说明](../UI_TESTING.md) |

当前没有用环境变量填写任意企业 API Key、endpoint 或 Token 单价的正式入口。
